ControllerHelper is a Windows 11 application for switching between a desktop monitor setup and gaming on a TV using a gamepad. It runs in the system tray and provides an overlay to switch to the TV, return to the monitors, enable the monitors alongside the TV, resume a game, and open Flydigi Space Station.

**ControllerHelper's own code was entirely generated by AI in response to user requests.** This is an experimental project: working on one computer does not guarantee compatibility with another TV, GPU, driver, or controller. Third-party libraries and protocol materials have their own authors and licenses.

## Download

[Latest Windows x64 release](https://github.com/eleaf33/controllerhelper/releases/latest) — download `ControllerHelper-…-win-x64.zip`, extract the **entire archive**, and run the top-level `ControllerHelper.exe`. No separate .NET installation is required. Logs are created automatically in `logs` beside the EXE. The release includes `SHA256SUMS.txt` for checking the archive's integrity.

**The public build does not include Hisense private keys.** Hisense MQTT pairing, input selection, and power-off are unavailable in this build; these features require a local build with the materials described below. Display and audio switching, Wake-on-LAN, and LG control do not require these keys.

The application supports **English and Russian**. English is the default, including when upgrading settings that do not contain a language preference. To change it, open **PC → Language / Язык**, select a language, click **Save settings**, exit through the tray, and restart ControllerHelper. The documentation language links above are independent of the application setting. Device names and messages supplied by Windows or drivers may follow the system language.

## Features

- Save a desktop monitor configuration and a separate TV profile.
- Switch displays, TV resolution and refresh rate; configure scaling where supported by Windows.
- Select separate PC and TV audio outputs. A temporarily unavailable HDMI output can be saved: after switching displays, the app waits up to 10 seconds for it to appear, then falls back to the selected PC output if TV audio remains unavailable.
- Automatically open Steam Big Picture when switching to the TV and close Big Picture when returning to the PC. Steam is required for “Play on TV” in the current version.
- Wake the TV over the network using Wake-on-LAN.
- Control LG webOS TVs: pairing, input discovery, HDMI selection, and power-off.
- Control compatible Hisense VIDAA TVs: PIN pairing, input selection, and power-off through the local RemoteNOW/VIDAA protocol.
- Open an installed Flydigi Space Station client within the overlay area and control the cursor with a gamepad.
- Configure an overlay button combination and a separate emergency return-to-monitors combination.
- Automatically write diagnostic logs to `logs` beside the top-level EXE.
- English and Russian settings, overlay, tray menu, pairing dialogs, status messages, and application errors.

## How it works

1. Select displays and audio devices for the PC and TV profiles.
2. The app receives events from the selected controller through Microsoft GameInput. A button combination opens the overlay.
3. Choosing “Play on TV” performs the configured wake and TV input selection, applies the Windows display configuration, selects audio, and opens Steam Big Picture.
4. Returning restores the PC monitors and audio first. Network power-off may then run for a configured and paired TV.
5. Switching operations run sequentially. Cancellation and errors are handled when restoring the previous state; an HDMI audio failure should not undo a successful display switch.

Displays are detected through the Windows Display Configuration API (`QueryDisplayConfig`, `SetDisplayConfig`), rather than fixed HDMI port numbers. Audio devices are enumerated through Windows Core Audio. Changing the default audio device uses the COM interface `IPolicyConfig`, which is not a publicly documented, stable Windows contract.

LG control uses webOS SSAP over WebSocket; Hisense uses local MQTT/TLS. These are separate network commands: an HDMI cable alone does not imply that a PC can wake the TV or select its input. Network control compatibility depends on the model and firmware.

Flydigi is launched through its own EXE. ControllerHelper waits for the client to show its main window, then positions that external window over the overlay. Flydigi source code and binaries are not included in this repository.

## Requirements

- Windows 11 x64, OS version `10.0.22000.0` or later.
- A controller available through Microsoft GameInput and the installed GameInput component.
- A TV connected to the PC's video output for display switching.
- A local network and TV remote control enabled for network features. Wake-on-LAN must be supported and enabled on the TV; its network interface MAC address is usually required.
- Steam installed and registered in Windows for “Play on TV”; the current version always opens Big Picture during that action.
- Flydigi Space Station installed separately if you want to use its overlay action.

The self-contained published build does not require a separate .NET installation. Building from source requires Windows, PowerShell, and **.NET SDK 10.0.401**, pinned in `global.json`. Hisense MQTT control also requires local compatibility materials described below; private keys are not published on GitHub.

## First run

Follow the **[complete setup guide](docs/SETUP.md)** for the exact controls, saving layouts, HDMI audio, network pairing, both-screen mode, updates, and troubleshooting. The short version:

1. Build the project using the instructions below or extract the complete release into a writable folder.
2. Run the top-level `ControllerHelper.exe`. Keep the `lib` and `lang` folders beside it.
3. On the PC tab (“ПК”), select monitors and audio, then save the current desktop configuration.
4. On the TV tab (“ТВ”), select the TV, audio output, and video settings.
5. Test local switching first with the TV already on. Then configure the LG or Hisense section for optional network control and choose the PC's HDMI input. Hisense MQTT requires a local build with its compatibility materials.
6. Select the controller and overlay button combination. The default is to hold **A + View for about 0.5 seconds**.
7. Save the settings and test switching to the TV and returning to the monitors.

In the overlay, the D-pad selects actions, A confirms, and B closes it. Emergency return is disabled by default. You can enable it in settings and assign a separate combination, such as holding LB + RB for two seconds. There is no automatic rollback timer after a display change.

Normal launch without administrator privileges is sufficient. To control Flydigi's external window, both apps need compatible access levels. When updating ControllerHelper, exit the old instance through the tray first: launching a second instance forwards its command to the running app.

## Build and verification

```powershell
git clone https://github.com/eleaf33/controllerhelper.git
cd controllerhelper
dotnet --version
.\verify.ps1
.\build.ps1
```

`verify.ps1` restores dependencies using lock files, runs the NuGet audit, builds Release, runs automated tests, and checks publication scripts. `build.ps1` repeats the required checks and creates a self-contained `win-x64` publication in `publish-controllerhelper`.

Publish to a separate folder:

```powershell
.\build.ps1 -OutputDirectory .work\publish-local
```

Output layout:

```text
publish-controllerhelper/
  ControllerHelper.exe   # launcher
  lib/                   # application, .NET, and dependencies
  lang/                  # language resources
  build-manifest.json    # publication contents and file SHA-256 hashes
  logs/                  # created at launch
```

Launch arguments: `--overlay` opens the overlay, `--to-tv` switches to the TV, and `--to-pc` returns to the PC. Launching without arguments opens settings.

Verification of the bilingual version passes **352/352 tests**, including translation coverage, matching format arguments, language persistence, and date/number formatting. Automated tests cover application logic, local TLS/MQTT scenarios, and the build; they do not guarantee compatibility with specific hardware. The latest Flydigi opening change still requires visual verification on the target PC.

English UI strings were checked with the LibreOffice English (US) spelling dictionary and reviewed in context. Terminology references and translation rules are recorded in [Localization/GLOSSARY.txt](Localization/GLOSSARY.txt).

### Local Hisense materials

The source builds and all tests run without TV protocol private keys. However, real Hisense MQTT control requires the client certificate and key for the relevant profile. Only the public certificate `vidaa_client.pem` is included in the source repository.

If you have lawfully obtained compatibility materials, place these files in `ThirdParty/Hisense/` before building:

- `vidaa_client.key` — the key matching the public `vidaa_client.pem` for the legacy profile;
- `remotenow_client.pem` — the RemoteNOW profile certificate and key;
- `vidaa_ios_client.pem` — the VIDAA V2 profile certificate and key.

These files are excluded by `.gitignore`; do not force-add them to Git. Then run `build.ps1`. Without them, Hisense MQTT pairing, input selection, and power-off report missing materials. Local display and audio switching, Wake-on-LAN, and LG do not require these keys.

A build made with local keys embeds them in application resources. Do not publish such binaries or archives as a workaround for excluding keys from the repository. Material sources and related notices are listed in [NOTICE.txt](ThirdParty/Hisense/NOTICE.txt). Test TLS clients use separate temporary certificates generated during the test run; these cannot replace real TV client certificates.

## Settings and diagnostics

Settings are stored in `%LOCALAPPDATA%\ControllerHelper\settings.json`; the previous valid version is kept in `.bak`. Pairing keys and tokens are protected with Windows DPAPI for the current user. Copying settings to another PC does not replace display configuration and pairing on that PC.

The `logs` folder contains `launcher.log`, `errors.jsonl`, and their rotated `.1` versions. JSONL records operation stages, timings, and diagnostic information as well as errors. A completed stage or a window's `visible=true` flag does not prove that an image actually appeared on screen.

Logs, user settings, and private keys are not included in Git. Review diagnostic files before sharing them publicly. Compatibility materials in `ThirdParty/Hisense` are not personal pairing tokens; their provenance and publication restrictions are documented in [NOTICE.txt](ThirdParty/Hisense/NOTICE.txt).
